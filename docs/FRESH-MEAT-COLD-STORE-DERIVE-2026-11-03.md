# 鲜肉：冷库余额改按记录层推导 + 收盘窗口判据（2026-11-03）

> 起因：owner 报**生产事故**——
> 「今天 11-03 需要搬上台 3 斤排骨，但是没有，看 ui 说冷库共 1 个 SKU，
> 但实际上昨天 11-02 日日终盘点有 3 斤排骨，还有其它 SKU，
> 11-02 日日终盘点进入冷库的 SKU，现在无法搬上台。」
>
> 修复提交：supertrade `e2327c9`（生产已部署，health 200 / auth_ok=true）

---

## 一、事故现场（部署前实测，生产）

```
GET /api/v1/fresh-meat/stock?scope=all   （店 00）
COLD 01407 leg_rear cold=2.4        ← 冷库只有 1 个 SKU
stock total_kg = 46.75              ← = 柜台 44.35 + 冷库 2.40
```

owner 看到的正是「冷库共 1 个 SKU / 2.40 kg」。

---

## 二、根因（生产数据 + 服务端日志双证）

### 事实链

| 事实 | 来源 |
|---|---|
| 11-02 的日终盘点 `created_at = 2026-11-03 00:27`（归属日 11-02） | `pork_cuts_stocktakes` |
| 11-02 进冷库的货：01401 排骨 1.5 / 01405 4.5 / 01407 6.5 / 01409 3.0 / 01426 2.0 / 01438 2.75 | `carryover_records`（source=stocktake, location=cold_store） |
| 位置表冷库侧只有 01407 = 2.4kg | `sku_stock_positions` |
| 冷库余额链（按营业日推导）是对的：合计 **70.15kg / 10 个 SKU** | `cut_stock_daily` 链路 |

### 机制

1. 门店的日终盘点**经常在午夜后提交**（11-02 的那张就是 00:27 交的）。
2. 旧判据 `resolveTakenDate` 用**日历日**比较 ⇒ `归属日(11-02) == 日历日(11-03)` 为假
   ⇒ 这张盘点被判成**「补录往日」**。
3. 「补录往日」分支**跳过 `applyOvernightMove`**（柜台 → 冷库的过夜搬运）
   ⇒ **那批货永远进不了位置表的冷库**。
4. 搬台页读的是位置表（`ListStock` → `loadSkuPositions`）
   ⇒ 门店只看到 01407 一个 SKU ⇒ **3 斤排骨搬不了**。

> 同样的形态在 10-29（00:42 交）、10-30（00:49 交）也发生过 ⇒
> 位置表的冷库侧**漏了三批货**，一直没人发现（库存查询页平时没人盯）。

### 为什么以前没人发现

`businessDayBounds` = `[当天 00:00, +24h)` ⇒ 营业日边界就是**日历日午夜**
⇒ 门店只要过了午夜再交盘点，就**永远**被判成「补录往日」
⇒ 「过夜搬运」这条路径**几乎从不执行**。

## 三、两条修法

### ① 冷库余额改成「按记录层推导」（新文件 `internal/fresh-meat/service/cold_store_derive.go`）

```
冷库(D) = 冷库(D−1) + 结转(D) − 搬上台(D) − 大宗出库(D) + 大宗进库(D) − 搭赠(D)
```

逐项对齐按部位的余额链（`deriveColdChain`）：

| 项 | 口径 |
|---|---|
| 结转 | 当天盘点盘出来的**柜台实盘**（per SKU） |
| 搬上台 | 当天搬台流水（per SKU）；**盘点日**且**没盘到的部位**要把账面柜台余额加回冷库（柜台被置零 ⇒ 货还在冷库） |
| 大宗出库 | 交付口径、且**从冷库领用**的那部分 |
| 大宗进库 | 手工补录的大宗产出（`carryover_records` source=`bulk_manual`） |
| 搭赠 | 搭赠出库（报损不进链），减完裁 0 |
| 起点 | 期初结转的生效日（整日重置，链外的余额不许漏进来） |

**为什么这样修**

- 提交得再晚也算得对（**补录往日照样生效**）⇒ **存量自动修好**，不用手工修数；
- **幂等**（推导不是累加）⇒ 同一张盘点重复提交不会翻倍；
- 位置表的冷库侧降级为「物理留痕」，**不再是对外口径**。

### ② 收盘窗口判据（`isClosingStocktake`）

```
归属日 D 的盘点，只要在 [D 00:00, D+1 04:00) 内提交 ⇒ 算「D 那天的收盘盘点」
```

⇒ **过夜搬运照跑**、**当前成本状态照刷**（`cut_cost_states` / `cut_cost_daily`）。

⚠️ `taken_at` / 归属日**不变** ⇒ 余额链与结转记录仍然归到那一天。

⚠️ 为什么不是「隔多久都算收盘」：真正补录往日时柜台已经摆着今天的货了 ⇒ 置零柜台会把今天的货也抹掉。

## 五、单测与判别力

`internal/fresh-meat/service/cold_store_derive_test.go`（5 条）：

| 用例 | 锁什么 |
|---|---|
| `MidnightStocktake_CarryoverIsVisible` | 午夜后提交的收盘盘点 ⇒ 冷库看得见那批货（owner 的原场景） |
| `LateBackfill_CarryoverIsVisible` | 隔天补录 ⇒ 冷库照样看得见（**锁①的判别力**） |
| `HistoricalMissedOvernightMove_CarryoverIsVisible` | 存量形态：库里已有那张午夜后提交的盘点单、位置表没有货 ⇒ 算得出来（**锁①的判别力**） |
| `MidnightStocktake_RunsOvernightMove` | 午夜后提交 ⇒ 过夜搬运照跑（**锁②的判别力**） |
| `SumBySkuEqualsPerCutChain` | 按 SKU 的合计 == 按部位的链（**逐位**） |

**判别力实测**（去掉实现 → 确认变红 → 恢复）：

| 去掉什么 | 变红的用例 |
|---|---|
| `loadSkuPositions` 冷库侧改回读位置表 | `LateBackfill`、`HistoricalMissedOvernightMove` |
| `isClosing` 改回 `isToday` | `MidnightStocktake_RunsOvernightMove` |

⚠️ 记录一个坑：第一次判别力实测用了 `if false { ... }` 做开关 ——
**Go 编译器会把 `if false` 的分支消掉** ⇒ 用例照样绿 ⇒ 那次实测**无效**。
判别力开关必须用**运行期变量**。

## 六、遗留：柜台侧仍不准（**本轮没修**）

这次只修了**冷库侧**。**柜台侧**（位置表 `location='counter'`）仍有老问题：

- 位置表的柜台侧**从来不记「当天分割出来的货」** ⇒ 白天柜台在架的货**不在这张表里**；
- 11-03 凌晨补录的 **4 笔外采**（10-30 12.25 / 10-31 11.0 / 11-01 9.7 / 11-02 11.4 = 44.35kg 排骨）
  全都累加在柜台余额上，而那几天的盘点单里**没有**它们 ⇒ 柜台显示 44.35kg 排骨。

⇒ 影响面：
1. 库存查询页的「柜台」列与「全店总量」（= 柜台 + 冷库）**偏大**；
2. 看板的**黄字告警「当前余额与按营业日推导的结余不一致」**会一直响（差值就是柜台那 44.35kg）。

⇒ 这条告警**部署前就在响**（那时差 −45.25kg），**不是本次改动引入的**。
⇒ 要根治得把柜台侧也改成推导（切出口径 + 外采 + 搬台 − 销售），属**另一件事**，
   本轮未做（owner 未拍板，且会牵动毛利链）。
