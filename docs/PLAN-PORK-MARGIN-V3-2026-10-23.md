# 猪肉毛利核算方案 v3 —— 以「日循环 + 移动加权平均」为主口径

> 目标:让**单日毛利**、**部位毛利**、**整猪毛利**都可算、且可对账。
> 状态:v3(2026-10-23)—— 按「售前盘点 + 日终盘点 + 加权平均」重构;
> 特价 SKU 改为**长期配置**(不再按日指定),归属靠**日终缺口分摊**。
> 上一版(v2)的全部结论仍然成立,本版是它的**上位方案**。

---

## 0. 一句话

**把猪肉当成普通零售存货管:SKU 级移动加权平均成本 + 售前/日终两次实盘。**
这样单日毛利变成一道**纯减法**,不再依赖 LLM 预估、不再依赖"猜昨天的货归哪头猪"。

```
本期毛利 = 本期销售收入 − (期初结存金额 + 本期入库金额 − 期末结存金额)
```

---

## 1. 现有算法最严重的缺陷(为什么必须换口径)

### ⚠️ 今天的猪没出过的部位,今天卖的钱成本是 0 ⇒ 毛利率 100%

```go
// gross_margin.go(第 219~274 行)
pigs := 当日进场的猪                       // ← 只有今天的猪!
costForCut[cut] = Σ pig(今天的猪) (pig_cost × 该猪该部位占比)
...
switch {
case purch.IsZero() && sold.IsZero(): ratio = 0
case purch.IsZero():                   ratio = 1     // ← 今天没产出 ⇒ 比例 100%
}
consumedCost := costForCut[cut].Mul(ratio)          // ← 但 costForCut = 0
```

⇒ 今天卖昨天剩的五花(今天没进猪 / 今天的猪没出五花):
**成本 = 0,毛利 = 收入,毛利率 100%。**
⇒ 不是偶发 —— **只要店里在卖隔夜货,每天都发生**。

### 现有算法完全没有"昨天"的概念

它把**今天卖的钱**一律按**今天进场的猪**的成本摊。所以:
- 卖昨天的货 → 用今天的猪的成本(错);
- 今天的猪出 A 部位、今天卖的是昨天的 A 部位 → 对不上;
- 今天没进的部位今天在卖 → 成本 0(见上)。

⇒ **这是"单日毛利"算不准的第一原因,也是"加权平均 + 期初盘点"直接解决的第一问题。**

### 其余 4 个缺陷(v2 已详述,此处只列结论)

| # | 缺陷 | 后果 |
|---|---|---|
| ② | 特价销售整行被丢弃 | 佳乐:金额 ~5%、重量 ~10% 消失 |
| ③ | 成本分摊基数只用 LLM advice;`history_avg` 返回空 cuts ⇒ 整猪成本摊不出去 | 毛利大幅**高估** |
| ④ | 猪身上未被任何部位覆盖的 kg(血、修割损耗、称重误差、**切分损耗**)成本也摊不出去 | 毛利高估 |
| ⑤ | 当日实盘按 cut **覆盖**而非累加(与期初口径相反) | 一个部位多 SKU 时实盘/差异全错 |

## 2. 新的日循环(核心结构)

### 售前(开店前)

| # | 动作 | 频率 | 落在哪 |
|---|---|---|---|
| ① | 确认**部位 SKU 映射**已覆盖当天会产生销量的 SKU | **长期配置**(映射变了才动) | `branch_cut_mappings` ✅已有 |
| ② | 确认**特价 SKU** 已确定 | **长期配置** | `promo_skus` 🆕 |
| ③ | 录**今日进猪**:头数 / 每头毛重 / 进价 / 品种 / 供应商 | 每日 | `whole_pigs` ✅已有(需在进场时录) |
| ④ | **售前盘点**:今天开卖时每个 SKU 有多少 kg(精确到 SKU) | 每日 | `pork_cuts_stocktakes`(kind=opening)🆕 |
| ⑤ | 自动:昨日日终 − 今日售前 = **隔夜损耗**(冷藏失重/滴水/漏盘) | 自动 | `waste_logs` 🆕 |

### 日间

| # | 动作 | 落在哪 |
|---|---|---|
| ⑥ | **分割单品补录**(`pig_cuts`:部位/重量/条码)—— 既是成本分摊依据,也是**分割模型的训练数据** | `pig_cuts` ✅已有(录入率是关键) |
| ⑦ | 零售销售 → POS → SKU 收入 | `line_sales_by_pigs` ✅已有 |
| ⑧ | **特价销售** → POS → promo SKU 收入(**不归属部位**) | 🆕 分支(数据已送到门口) |
| ⑨ | **大宗产出**:板油余量录入(扣掉零售后的余量) | `bulk_productions` 🆕 |

### 日终

| # | 动作 | 落在哪 |
|---|---|---|
| ⑩ | **日终盘点**:每个 SKU 剩余多少 kg | `pork_cuts_stocktakes`(kind=closing)✅已有 |
| ⑪ | **核算**:移动加权平均 → 单日毛利 / 部位毛利;特价分摊;成本对账行;切分损耗;隔夜损耗 | `gross_margin.go` 改写 |

> **⑤ 的价值**:隔夜损耗以前完全没人管(昨天的 100 斤今天变 98 斤,这 2 斤成本凭空消失)。
> 有售前+日终两次实盘,它自动浮出来 ⇒ **能算到哪天的货少了多少**。

## 3. 成本核算主口径:移动加权平均(per SKU)

### 3.1 公式(每个 SKU 独立算)

```
期初数量 Q0 = 售前实盘 kg
期初金额 V0 = Q0 × 昨日该 SKU 的移动加权单价

本期入库数量 Q1 = 今日分割产出到该 SKU 的 kg(单品补录优先,LLM/统计兜底)
本期入库金额 V1 = Σ(今日产出该 SKU 的每头猪的成本分摊额)

可售总金额   = V0 + V1
可售总数量   = Q0 + Q1
本期移动加权单价 = 可售总金额 / 可售总数量

期末数量 Q2 = 日终实盘 kg
期末金额 V2 = Q2 × 本期移动加权单价

本期销售成本 = 可售总金额 − V2
本期销售毛利 = 本期销售收入 − 本期销售成本
```

**本期入库金额 V1 的算法**(仍然是唯一需要"把猪成本摊到部位"的地方):
```
对每头今日进场的猪 P:
  P 的总成本 = 进价 × 毛重(或直接录采购金额)
  P 分割出的各 SKU kg = 单品补录;缺失则用统计基线(§6)预估
  P 的各 SKU 成本分摊 = P 总成本 × (该 SKU kg / P 的产出 kg 合计)
```
⇒ 注意分母用 **P 的实际产出合计**,不是 `gross_weight` ⇒ **差额自动就是"切分损耗"**(§5)。

### 3.2 为什么这个口径明显更准

| 维度 | 现有(LLM 摊销) | v3(移动加权平均) |
|---|---|---|
| 卖昨天的货 | 用**今天**的猪的成本,今天没进猪则成本 **0** ⇒ 毛利 100% | 期初按**昨日移动加权单价**入账 ⇒ 成本真实 |
| 隔夜损耗 | 无记录,成本凭空消失 | 售前 vs 日终差额 ⇒ **显式损耗** |
| 切分损耗 | 无记录(进猪 kg − 产出 kg 的差额消失) | 自动浮出 ⇒ 显式损耗 |
| 多日累积库存 | 无概念 | 移动加权天然处理 |
| 可对账 | ❌ 没有对账行 | ✅ `Σ 各 SKU 销售成本 == Σ 当日猪采购成本 + 期初存货成本` |

### 3.3 状态持久化

```
sku_cost_daily(                      -- 日快照,可审计、可回看每天怎么算的
  branch_id, biz_date, cube_product_id,
  opening_qty, opening_amount,
  purchased_qty, purchased_amount,
  sold_qty, sold_amount,
  closing_qty, closing_amount,
  moving_avg_unit_cost,
  data_source            -- actual | partial | estimated
)
```
⇒ 昨日的移动加权单价 = 昨日快照的 `moving_avg_unit_cost`;递归基准由此而来。

## 4. 特价 SKU:长期配置 + 日终缺口分摊

### 4.1 配置(长期,像部位映射一样)

```
promo_skus(
  id, branch_id, cube_product_id, product_name,
  note, active, created_at, updated_at
)
UNIQUE(branch_id, cube_product_id)
```
⇒ **用户已确认:这是长期设置,像部位 SKU 映射一样,不需要每天动。**

### 4.2 特价销售怎么落库(数据已在门口)

`sale.completed` 里本来就带着 `sku_id / qty / amount` —— 只是被
"查不到 `branch_cut_mappings` 就丢行"这一句丢掉了。
⇒ **在解析处加一个分支**即可:

```
若 sku_id 命中 promo_skus:
    → 落 line_sales_by_pigs(cut_type = "promo", source = "pos_promo")
    → 金额与 kg 都进来(满足"囊括进来")
    → 部位归属留待日终分摊
```

### 4.3 日终分摊(有了期初之后,分摊从"推断"变成"可对账的差值")

```
对每个部位 c:
    gap_c = 期初_c + 入库_c − 正常销量_c − 日终剩余_c − 已记报损_c
```
- `gap_c > 0` ⇒ 该部位"账面少了这么多 kg" ⇒ 被特价处理了(或有未记损耗);
- **`gap_c` 就是该部位的特价 kg**(前提:切分损耗/隔夜损耗已单列,不再混在里面);
- 特价总量 `K = Σ 特价销售行.kg`(实测);`R = Σ 特价销售行.amount`(实测);
- 权重:缺口为主 + 滞销度(周转天数)为辅(α=0.7),详见 v2 §3.2;
- `promo_kg_c = K × w_c`,`promo_amount_c = R × w_c`;
- 残差(舍入/权重不匹配)进"未分摊残差"行,显式列出。

### 4.4 有期初之后,分摊的重要性**下降**了

因为移动加权平均把**成本和收入绑在同一个 SKU 上**:
- 之前:分摊错了 ⇒ 收入归错部位 **且** 成本归错(两处错);
- 现在:分摊错了 ⇒ 只影响"特价收入记到哪个部位"(成本跟着该部位的移动加权单价走,自动一致)。

⇒ **即使分摊只是"大致对",单日毛利与部位毛利也已经基本准。**

### 4.5 盘点时特价档上的货怎么记?

现实里档口上有个"特价档",上面摆着当天的特价货,盘点会盘到。
⇒ **盘点单按 SKU 记**,特价货号那一行的 `cut_type` 记 `promo`(未归属),
由分摊算法在事后回填,或作为"特价档库存"单列。
(这一条在实施时需要确认门店的物理摆放方式。)

## 5. 显式化的三个"消失的 kg"(以前全部被吃掉)

| 项 | 公式 | 来源 |
|---|---|---|
| **切分损耗** | 今日进猪毛重 − 今日产出 SKU kg 合计 − 今日大宗产出 | 自动 |
| **隔夜损耗** | 昨日日终盘点 − 今日售前实盘(逐 SKU) | 自动 |
| **未分摊残差** | 移动加权对账行里的差额 | 自动 |

⇒ 这三项以前**都不在任何表里**,成本凭空消失 ⇒ 毛利虚高。
⇒ 有了它们,**猪的钱和猪的 kg 100% 闭合**。

## 6. 分割重量预测:数据能积累,但**建议别用 LLM 做数值回归**

### 6.1 数据来源(已经有了)

- `whole_pigs`:体重、品种、供应商、进价、进场日期
- `pig_cuts`:**每头猪实际分割出的各部位 kg** ← 这就是标签

⇒ 一头猪 = 一个样本,每个部位一个标签。**样本已经在攒了**,只要单品补录的录入率上来。

### 6.2 ⚠️ 但 LLM 不适合这个任务

"300kg 的猪能出多少五花肉"是**数值回归**问题。
- LLM 在 prompt 里"回忆"历史,给的是语言模型的先验,不是从样本拟合出来的;
- 同一体重段的猪,分割差异来自品种/膘情/季节/师傅手法 —— 这些是**结构化特征**,该用统计/回归模型;
- 统计/回归模型:**更准、更快、更便宜、可解释**(能直接给出"体重 280~320kg 段的五花均值 38kg ± 4kg")。

⇒ **建议**:
| 阶段 | 预测器 | 说明 |
|---|---|---|
| **短期(马上)** | **分层统计基线**:按 `体重段 × 品种` → 各部位均值 + 分位数 | 不需要任何模型,`pig_cuts` 一有就能算;比现在的 LLM 准 |
| **中期** | 回归模型(梯度提升),特征:体重/品种/供应商/季节/膘情 | 样本够了再上;仍然比 LLM 便宜一个数量级 |
| **LLM 的新定位** | **兜底 + 解释层**:没有历史样本的冷启动情况,以及"这头猪分割异常"的文字解释 | 不再让它承担数值精度 |

### 6.3 样本量现实感

1 头/天 ⇒ 1 年 ≈ 365 头。若按 `体重段(10) × 品种(3)` 分格 ⇒ 每格约 12 头 ⇒ **勉强能用**。
⇒ 想要更细的建模,需要**多店数据汇聚**(佳乐 + 富百家 + 后续门店)或**更长的历史**。
⇒ 这也说明:**推动单品补录的录入率,本身就是最有价值的投资** ——
它同时是成本分摊的依据、分割模型的训练数据、特价分摊的精度来源。

## 7. 大宗台账(板油,沿用 v2,按 Q1/Q2/Q3)

- 录入口径 = **扣掉零售后的余量**(与零售完全互斥)
- 猪归属 = 计算时按当日各猪 `gross_weight_kg` 比例分摊
- 结算 = **交付离店**:产出(+) → 结算(−,收入),FIFO 分配到产出记录
- 结算金额**回写 `line_sales_by_pigs`(source=bulk, cut_type=fat, 记在产出日)**
- 板油那部分 kg **不进 pig_cuts**(避免与零售部位重复),但要进**成本分摊的分母口径**
  ⇒ 切分损耗公式里要减掉大宗产出

## 8. 能计算到什么程度(能力清单)

| 口径 | 粒度 | 精度 | 前置 |
|---|---|---|---|
| **单 SKU 单日毛利** | SKU × 日 | **高**(零售会计标准,移动加权) | 售前 + 日终盘点 + 单品补录 |
| **部位(切)单日毛利** | 部位 × 日 | **高**(部位毛利 = 其下各 SKU 汇总) | 同上;**不再受"今天没进猪"影响** |
| **门店单日毛利** | 店 × 日 | **高** | 同上 |
| **特价分摊明细** | 部位 × 日 | 中(缺口法,可对账) | 同上 + 特价 SKU 配置 |
| **整猪毛利** | 猪 | 中(归因口径) | 单品补录 + 二次分摊(§9.2) |
| **隔夜损耗 / 切分损耗** | SKU / 店 × 日 | **高**(实测差额) | 售前 + 日终盘点 |
| **分割重量预测** | 部位 | 中→高(样本积累) | `pig_cuts` 录入率 |
| **成本对账行** | 店 × 日 | **高**(误差应为 0) | 全部 |
| **盘盈亏 / 账实差异** | SKU × 日 | 高 | 两次实盘 |
| **单猪的"分割异常"识别** | 猪 | 中 | 预测 vs 实际,样本够后 |

**还不能算准的(要诚实说)**
- **单猪毛利**:库存混合后,卖出去的货归哪头猪只能用 FIFO/比例近似(单猪层面没有实盘);
- **特价归属**:缺口法是推断,不是实测;只有当某天只有一个部位有缺口时才接近确定;
- **未记录损耗**:切分/隔夜能自动算,但"分割过程中掉地上/被偷"这类仍不可见。

## 9. 取舍与隐患

### 9.1 必须接受的三条

| # | 取舍 | 说明 |
|---|---|---|
| T1 | **成本法切换** | 移动加权与旧的 LLM 摊销**口径不同,历史不可比**。需要定一个"切换日",之前的报表标注为旧口径。 |
| T2 | **售前盘点是新增的日常动作** | 门店执行成本。漏盘 ⇒ 期初错 ⇒ 当天毛利错。⇒ 系统要做**漏盘检测**(与昨日日终值差异过大就告警),并把"是否已盘"作为报表的显式标记。 |
| T3 | **两套成本口径并存** | 移动加权(SKU/部位/店级,权威零售口径)+ 逐猪归因(整猪,管理口径)。两者会有差,这个差本身是重要指标(说明混合/损耗/盘亏)。**报表必须分别标注,不能混。** |

### 9.2 建议一起做的两个"白送"红利

1. **二次分摊到单猪**(v2 §5.2):店级分摊后,按"该部位各猪的入库 kg"再分一次 ⇒ 单猪也拿得到特价收入。**否则"整猪毛利"其实还是店级。**
2. **分割重量预测先上统计基线**(§6):不依赖 LLM,`pig_cuts` 一有就能算,立刻提升成本分摊与特价分摊的精度。

### 9.3 其它隐患(沿用 v2,此处不重复)

- 缺口 ≠ 特价 ⇒ **总量用实测,缺口只定比例**;
- LLM 高估会让真凶的缺口变负 ⇒ `应产出`优先用 `pig_cuts` 实际值;
- 分摊结果**不落回**销售表(避免自反馈);
- 硬依赖 `is_complete` 盘点 ⇒ 降级路径要显式。

## 10. 实施顺序

| 阶段 | 内容 | 验收 |
|---|---|---|
| **P0** | **售前盘点**(opening kind)+ 隔夜损耗自动识别 | ①能录每个 SKU 的期初 kg;②昨日日终 vs 今日售前差额自动进损耗 |
| **P1** | **移动加权平均核算**重写 `gross_margin.go` | ①"今天没进猪的部位今天在卖"不再出现 100% 毛利(回归测试);②成本对账行误差恒为 0;③卖昨天货的成本 ≈ 昨天的成本 |
| **P2** | **特价 SKU 长期配置** + 销售行不再被丢弃 + `promo` 枚举 | ①特价销售行落库;②"特价未归属"金额与源库对账一致 |
| **P3** | **日终缺口分摊** + 分摊明细 + 二次分摊到单猪 | ①各部位 promo kg 之和 == 实测特价 kg;②分摊明细含权重与依据;③降级路径有明确输出 |
| **P4** | **切分损耗 / 隔夜损耗** 显式化 | 进猪 kg − 产出 kg − 大宗 = 切分损耗,自动入账 |
| **P5** | **板块油大宗台账** | ①录入余量 → 结存可见;②结算 → 对应猪毛利出现收入;③零售与大宗 kg 不重复 |
| **P6** | **分割重量统计基线**(替代 LLM 数值预测) | ①按体重段×品种给出各部位均值与分位数;②新猪入库时用基线预估产出,并随实际补录滚动修正 |
| **P7** | Flutter 前端 + deployer 契约测试 + 部署 | 三仓测试全绿 + 生产部署 + 契约测试打生产 |

> **P1 是整件事的核心** —— 它把"单日毛利"从"猜"变成"算"。
> P0 是它的前置(没有期初就没有移动平均)。
