## 1. 背景与问题陈述

### 1.1 业务背景

超市资金流有三个特点：**笔数多、渠道杂、时效紧**。

- 收入侧：收银台有现金、微信、支付宝、银行卡、储值卡、团购挂账等多种收款方式，每天闭店后要清点现金、核对各渠道到账。
    
- 支出侧：走企业微信审批后付款、门店房租水电、员工报销、零星采购。
    
- 银行侧：账户有 POS 结算入账、平台（美团/饿了么/抖音）结算入账、供应商付款出账。
    

### 1.2 当前痛点（出纳视角）

1. **收银系统流水与银行到账对不上**：POS 结算通常 T+1 到账且扣手续费，微信/支付宝有单独结算周期，出纳要手工逐笔比对，日终经常差几十块找不到原因。

### 1.3 需求目标

- 日终对账从"手工逐笔"变为"系统自动匹配 + 人工只处理差异"。
    
- 所有资金往来（收与付）有唯一权威记录，可追溯、可审计。
    
- 差异（长短款、未匹配、手续费）有明确归因和台账。

## 2. 用户角色与使用场景

| 角色       | 核心诉求              | 使用频率  |
| -------- | ----------------- | ----- |
| 出纳（主要用户） | 每日对账、差异处理、付款登记、报表 | 每日    |
| 收银主管     | 查看本班次长短款、确认交班     | 每日    |
| 财务经理/老板  | 看资金日报、应收应付汇总      | 每日/每周 |
| 采购       | 查供应商付款是否已付        | 按需    |

**典型场景**：

- 场景 A（日终对账）：闭店后，出纳打开系统，系统已自动拉取当日收银系统流水和银行入账流水，自动匹配，出纳只处理标红的差异项。
    
- 场景 B（付款登记）：企业微信审批通过的付款单自动进入对账清单。
    
- 场景 C（临时收款）：团购客户微信转来一笔货款，出纳在系统录入"其他收款"，指定来源和归属门店。
    
- 场景 D（月度汇总）：老板要应付账款余额，出纳一键导出"未付款"清单。

## 3. 功能需求

### 3.1 收入侧对账

**FR-01 收银流水接入**

- 从收银系统（POS）按日拉取流水，字段包括：门店、收银员、班次、支付方式、应收金额、实收金额、交易时间、交易号。
    
- 支持按支付方式汇总：现金、微信、支付宝、银行卡、储值卡、挂账等。
    

**FR-02 银行及渠道流水接入**

- 对公账户流水：手工导入银行流水文件（Excel/CSV）或对接银企直连（二期）。
    
- 第三方渠道结算：微信/支付宝/美团/抖音的结算单导入，需能识别平台手续费。
    
- 每笔渠道流水记录：到账时间、到账金额、手续费、结算批次号。
    

**FR-03 自动匹配**

- 匹配规则（可配置优先级）：
    
    1. 金额 + 日期（T+1 容忍）匹配；
        
    2. 结算批次号与收银系统批次号匹配；
        
    3. 金额差额等于已知手续费率时，判定为"手续费差异匹配"。
        
- 匹配结果三态：**已匹配、金额差异、未匹配**。
    

**FR-04 现金长短款管理**

- 按"门店 + 日期 + 班次 + 收银员"维度，记录系统应收现金 vs 实际交班现金。
    
- 差异自动生成长短款记录，需收银主管确认原因（找零错误/漏扫/其他），出纳复核。
    
- 长短款台账可按收银员汇总，供绩效参考。
    

**FR-05 其他收款录入**

- 录入字段：日期、金额、收款方式、付款方、事由、归属门店、凭证附件（照片）。
    
- 支持从共享表格批量导入草稿，导入前校验必填项和金额格式。
    

### 3.2 支出侧对账

**FR-06 付款审批单接入**

- 从企业微信审批拉取付款审批单：审批单号、申请人、收款方、金额、事由、审批完成时间、审批状态。

**FR-07 付款登记与核销**

- 支持手工录入付款明细

**FR-08 供应商应付台账**

- 按供应商汇总：已审批未付、已付金额、账期到期提醒。
    
- 付款与供应商对账单关联，支持导出对账函。
    

### 3.3 对账引擎与差异处理

**FR-09 对账任务**
    
- 对账结果生成"对账批次"，记录批次号、对账日期、匹配率、差异笔数。
    

**FR-10 差异处理工作台**

- 差异分类：金额差异、单边账（有收无付/有付无收）、重复记录、手续费差异、时间差未到账。
    
- 每笔差异可执行：人工匹配、标记为合理差异（填原因）、挂起待查、转异常上报。
    
- 所有人工操作留痕：操作人、时间、原值、新值、原因。
    

**FR-11 人工覆盖与审计**

- 人工匹配或修改状态必须填写原因，系统记录修改日志，不可物理删除记录。
    
- 支持按审批单号/流水号反查全部关联操作历史。
    

### 3.4 报表与看板

**FR-12 资金日报**

- 当日：各支付方式收款额、银行到账额、差异额、长短款合计、当日付款额、待付款笔数。
    
- 支持按门店拆分。
    

**FR-13 对账结果看板**

- 展示：匹配率、未匹配清单、差异趋势（近 7 日/30 日）。
    
- 看板数据以只读方式同步到共享表格，供老板和财务经理查看；表格端不可直接改数，需改动走系统内流程。
    

**FR-14 导出**

- 支持导出：日对账明细、长短款台账、应付台账、差异处理记录，格式 Excel/PDF。
    

### 3.5 权限与配置

**FR-15 角色权限**

- 出纳：对账操作、付款登记、其他收款录入。
    
- 收银主管：查看本门店长短款、确认交班差异。
    
- 财务经理：全部查看、差异复核、规则配置。
    
- 老板：只读看板与日报。
    

**FR-16 规则配置**

- 匹配规则、手续费率、T+N 到账容忍天数、长短款容差阈值（如 ±5 元内自动标记"合理差异"待确认）可配置。

## 4. 非功能需求

| 类别    | 要求                                  |
| ----- | ----------------------------------- |
| 数据可靠性 | 对账权威数据存于数据库，共享表格仅作展示与草稿；关键状态变更记审计日志 |
| 性能    | 单店日流水 5000 笔以内，对账任务 5 分钟内完成         |
| 时效    | 收银流水、渠道结算单支持 T+1 拉取；银行流水支持手工导入即时生效  |
| 安全    | 金额相关操作二次确认；导出含敏感信息需授权               |
| 可追溯   | 任何记录可反查来源单据和操作历史，保留期不少于 3 年         |
| 易用性   | 差异处理工作台支持键盘快捷操作，减少逐条点击              |

## 5. 关键业务规则（出纳视角的"红线"）
    
1. **差异不允许直接删除**，只能标记原因或挂起，保证审计链完整。
    
2. **共享表格不是账**。表格里的数只作参考，一切以系统数据库为准；表格端修改需回流系统并经复核。
    
3. **手续费必须单列**，不能把"到账金额=应收金额"硬凑平，否则毛利失真。
    

---

## 6. 验收标准（摘要）

- 给定一日收银流水与银行流水，系统自动匹配率 ≥ 90%（现金类除外），出纳处理剩余差异 ≤ 30 分钟。
    
- 任一长短款记录可追溯到门店、班次、收银员及确认人。
    
- 资金日报数据与系统明细逐项可勾稽，误差为 0。
    

---

## 7. 分期建议

- **一期（MVP）**：自动匹配、差异工作台、付款审批数据同步、资金日报、长短款台账。
    
- **二期**：银企直连、第三方平台结算单自动对接、应付账期提醒、共享表格只读看板自动同步。
    
- **三期**：多门店汇总、毛利联动分析、异常交易预警（如大额现金、频繁退款）。

这份文档的落脚点是：**出纳要的不是"更花哨的表格"，而是"差异自动收敛、每笔钱有据可查"**。如果后续要转成研发排期，建议优先把 FR-03（自动匹配）、FR-07（付款核销）、FR-10（差异工作台）。

架构层建议和需求澄清：
收银流水遵循门店有源查cube源，无源查本地PG，如本地PG无该模块或不满足，请根据cube源设计需求和临时处理方案并将其记录到POS收银待开发功能文档。
企业微信付款审批单流程走到处理人为”未付款“，处理人处理并审批结束为”已付款“。
支付方式分析cube源来参考确定。
企业微信付款项落入对账系统后，可作为”门店每月有且仅有1张“逻辑判断总表用，解决审批单积累很多之后性能下降问题。
设计审核结算功能，因为对账流水除企微审批外的收录是可修改变更的，收银流水是实时同步，实时查的，只有当审核计算时才冻结对账流水、快照收银流水。审核完后做期末快照，下一轮以上一轮期末为期初进行。
