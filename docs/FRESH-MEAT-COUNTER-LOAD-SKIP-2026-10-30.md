# 鲜肉 · 「今天不搬台」（0 kg 标记行）设计与口径（2026-10-30）

> 线1：**鲜肉 → 每日工作 → 搬台**
> 门店原话：「有时候整日都不需要搬台，我找不到 0 搬台的操作办法，0 搬台会影响其它计算吗？」

---

## 0. 结论先写

| 问题 | 结论 |
|---|---|
| 之前为什么做不到 | 后端 `qty_kg` 必须 **> 0** ⇒ 门店**没法表达**"今天不搬台" ⇒ 每日作业第②步永远显示"未搬台" |
| 现在怎么做 | 落一条 **0 kg、没有货号** 的搬台流水当标记（前端一个按钮） |
| **影响其它计算吗** | **数值上零影响**（所有计算都是加减 0）；但**两个状态判定必须把它排除**，否则口径反了（见 §2） |
| 会不会污染链起点 | **不会** —— 链起点（期初生效日）当天**禁止任何搬台**（含 0 kg）⇒ 标记行落不进去 |

---

## 1. 数据落地长什么样

`counter_loads` 表多一行：

```
id = CLD-{branch}-{yyyymmdd}-{seq}
cube_product_id = ''        ← 没搬货 ⇒ 没有货号
qty_kg         = 0
cut_type       = ''
source         = 'sku'
```

`GET /stock/counter-load` 多回一个字段（**snake_case**，前端靠它显示"已确认今天不搬台"）：

```json
{
  "total_kg": "0",
  "has_counter_load": false,
  "counter_load_skipped": true,   ← 新增
  "lines": [ { "qty_kg": "0", "cube_product_id": "" } ]
}
```

⚠️ `counter_load_skipped = true` 的条件 = **存在 0 kg 的行** 且 **当天总搬台量 = 0**
⇒ 又搬了货又有标记行 ⇒ 以"搬过"为准（口径不打架）。

---

## 2. 影响什么 / 不影响什么

### 2.1 **不影响**（数值上全是加减 0）

| 计算 | 为什么不受影响 |
|---|---|
| 冷库余额 / 柜台余额 | 搬台量加 0 ⇒ 位置表不动（`cube_product_id` 为空 ⇒ 也不凭空多一行） |
| 成本链 / 部位单价 | 成本链按**搬台量**推 ⇒ 加 0 |
| 毛利 / 营收 / 成本 | 全部由销量与成本链决定 ⇒ 不动 |
| 分割倒推 | 倒推用「期初 + 进 − 销 − 报损」⇒ 搬台不在式子里 |

### 2.2 **必须排除**的两处状态判定（否则口径反了）

| 判定 | 为什么必须排除 0 kg |
|---|---|
| `hasBizDayActions`（营业日动作） | 期初生效日若是"**纯基线日**"（没有任何营业日动作）⇒ 那天的日终 = 期初本身 ⇒ 链从那里开始 ⇒ **不需要盘点单**。若 0 kg 被当成"搬过台"⇒ 那天变成营业日 ⇒ 门店被迫补一张**补不出来的**盘点单（那天的货还没卖过）⇒ **链会断** |
| `isRestDay`（鲜肉休市） | 口径是「当天既没进猪、也没搬冷库商品上台」⇒ 休市。"确认今天不搬台"恰恰说明**没搬** ⇒ 那天仍是休市 |

⚠️ `hasBizDayActions` 的过滤还有第二重用处：**链起点会随改期初而前移**
（改期初 = 换链起点）⇒ 新链起点那天**可能已经有搬台流水** ⇒ 那时 `qty_kg > 0` 的过滤才真正起作用。

### 2.3 状态机与前端

| 位置 | 行为 |
|---|---|
| `business_days.has_counter_load` | 0 kg **不置**（还是 false） |
| `business_days.status` | 0 kg **不推进**状态阶梯（还是 `no_pig` / 上一步的状态） |
| `business_days.counter_load_kg` | 按流水重算 ⇒ 0 kg ⇒ 仍是 0 |
| 前端 `DailyState.hasCounterLoad` | 改成看**总搬台量 > 0**（不看"有没有流水行"）⇒ 否则 0 kg 会被误判成"搬过台" ⇒ **休市预判就不对了** |
| 前端第②步状态 | 新增 `DailyStepStatus.skipped`（「不搬台」）⇒ 算"这一步已确认"，但**不是**"已搬台"，图标也区分开 |

---

## 3. 一条被特意放开的校验

「**前一个营业日必须已盘点**」这条跨日顺序校验，对 0 kg 标记行**不适用**：

- 那条校验是为**真搬台**服务的（搬货要拿昨天的日终当基线）；
- 0 kg 标记**不动货、不改余额链** ⇒ 没有基线问题；
- ⇒ 不能因为昨天没盘点，就把门店"记一笔今天没搬台"这件事也挡住
  （那会让门店在"整日不搬台"的日子**点不动按钮**）。

⚠️ 反过来：**真搬台仍必须被挡** ⇒ 校验不能被 0 搬台"带跑"（契约测试两条一起锁）。

## 4. 前端入口

`lib/ui/fresh_meat/stock/counter_load_skip_note.dart`（新）：

- 「已录搬台」区块下方一行：**没搬过货** ⇒ 给「今天不搬台」按钮；
- **已经搬过货** ⇒ 不给（搬过了就别再标"不搬台"）；
- **已经标过** ⇒ 显示「已确认：今天不搬台（不影响任何计算……）」；
- **冷库没货**时（"整日不需要搬台"的日子往往就是没货）⇒ 空态页**也**给这个入口。

提交的行：`CounterLoadLineInput.skip()` ⇒ `{"qty_kg": 0}`（**不带** `cube_product_id`）。
