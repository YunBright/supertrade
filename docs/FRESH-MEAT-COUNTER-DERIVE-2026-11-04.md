## 二、根因一：外采进了「本期入库」，但**POS 里没有对应的卖出**

### 事实链（生产实测，店 00）

| 事实 | 来源 |
|---|---|
| 四笔外采都是 01401 肋排：10-30 12.25kg / 10-31 11.0kg / 11-01 9.7kg / 11-02 11.4kg | `external_purchases` |
| 四笔的 `created_at` 全在 **2026-11-03 09:30~09:32**（门店 11-03 上午一次性补录了四天） | `external_purchases` |
| 11-02 思迅日汇总里 01401 只有 **19.1571kg / 760.20 元**（引擎读到的就是它，没丢数据） | cube `sales_report` |
| 11-02 全量 610 行里**没有任何货号**的 qty ≈ 11.4 | cube 全量扫描 |
| 缺口**恰好等于当天外采量**，四天全中 | `gift-suggestions` × 4 |

### 机制

```
外采(11.4kg) ──► 本期入库(prodK) ──► 账面应有 12.9kg
                                     − 卖出(只认 POS 的 19.16kg)
                                     = 12.9kg  ⇒ 比实盘(1.5kg)多 11.4kg
```

外采是**门店手工补录**的事实（owner 口径：「当天买、当天卖完；卖不完的会在日终盘点体现」）。
它进了库存，但**思迅的日汇总里没有这一笔** ⇒ 系统永远等不到那个出口 ⇒
**凭空多出一堆货** ⇒ 被当成「疑似搭赠」⇒ 门店点一下就白扣 241 元毛利。

### 修法：外采按「当天进、**当天出**」（pass-through）处理

`internal/fresh-meat/service/cut_cost.go`：

```go
externalOutKg := extProducedKg[c]
expectedCloseKg := availKg.
    Sub(partSoldKg[c]).Sub(partBulkKg[c]).Sub(partWasteKg[c]).Sub(partGiftKg[c]).
    Sub(externalOutKg)          // ← 外采自己带一个出口
```

- **成本照进销售成本**（owner：「进货成本变高了」）—— 这一条**不动**。
- 账面应有里**不留**它 ⇒ 缺口归零 ⇒ 不再误报搭赠。

### 口径变更的影响面（部署前后逐位对比实测）

| 项 | 变化 |
|---|---|
| `expected_remain_kg`（账面应有） | 变（11-02：12.9 → **1.5** = 实盘） |
| `variance_kg`（盘盈亏） | 变（11-02：−11.4 → **0**） |
| 搭赠核对卡 | 11-02 的那条**消失**（count 1 → 0） |
| **收入 / 销售成本 / 毛利 / 毛利率 / 期初 / 期末 / 售价 / 参考口径** | **逐位相同（0 差异）** |

> 有盘点单的日子：期末量 = 实盘 ⇒ 销售成本**逐位不变**；
> 没盘点单的日子：期末量 = 账面推演 ⇒ 外采不再留在存货里
> ⇒ 它的成本**全额**进当天销售成本 ⇒ 毛利**下降**（更保守、更接近真相）。

## 三、根因二：位置表的柜台侧**只累加、不扣零售卖出** ⇒ 幽灵库存

### 事实链（生产实测，店 00）

```
sku_stock_positions：01401 / counter = 44.350 kg
```

= 10-30/10-31/11-01/11-02 **四笔外采之和** —— 而这 44.35kg **早卖完了**。

### 机制

1. 位置表的柜台侧**只做加法**：搬上台 +=、外采 +=、大宗领用 −=、过夜搬运**置零**。
2. 它**从来没有扣过零售卖出** ⇒ 余额**只涨不跌**。
3. 位置表柜台侧只在**过夜搬运**（盘点夜）时置零；
   而四笔外采都是 11-03 上午补录的 ⇒ **全部写在 11-02 收盘盘点（11-03 00:27 置零）之后**
   ⇒ 再也掉不下去。

### 连带后果

每日毛利的「余额与按营业日推导不一致」黄字，一直报：

```
rib 当前余额 45.85 kg 与按营业日推导的结余 1.5 kg 不一致(差 -44.35 kg)
```

### 修法：柜台侧改按记录层推导（新文件 `internal/fresh-meat/service/counter_derive.go`）

```
窗口 = (最近一次日终盘点的**归属日**, 今天]

柜台(SKU) = Σ_{d ∈ 窗口}[ 搬上台(d) + 外采(d) + 分割产出(d)
                          − 零售卖出(d) − 大宗柜台领用(d) − 报损(d) − 搭赠(d) ]
         ⇒ 裁 0
```

| 项 | 口径 |
|---|---|
| 窗口起点 | 最近一次日终盘点的**归属日**（**不按提交时刻**）⇒ 补录的往日盘点不会把柜台算成历史值 |
| 归属日 ≤ 锚点日的事件 | **整体排除** ⇒ 那一批货已被当晚的实盘吸收 ⇒ **幽灵余额消失** |
| 分割产出 | **引擎同一套口径**（`computeProducedBySku`：pig_cuts 实录 → 统计基线 p50 → LLM 兜底）⇒ 库存页与毛利看板讲的是同一批肉 |
| 零售卖出 | 有源门店读思迅日汇总（cube）；无源门店读本地收银事件 |
| 位置表的角色 | 降级为**物理留痕**（过夜搬运要搬它**真实记着**的余额）⇒ 不能换成推导值 |
| 推不出来 | 这家店**没有盘点单** ⇒ 退回位置表 + **大声**记日志（失败必须可见） |

> **为什么柜台是「当天之内」的量**：柜台每天夜里被清零（过夜搬运：柜台置零、实盘进冷库）
> ⇒ 盘点那一刻数出来的柜台实盘是**冷库链的结转**，不是柜台的起点（柜台那晚已经是 0 了）。

### 生产实测（部署后）

```
GET /api/v1/fresh-meat/stock?scope=all   （店 00）
01401 rib cold=1.5 counter=0      ← 幽灵余额 44.35 消失，冷库 1.5 不动
01407 leg_rear cold=28.15 counter=7.717   ← 柜台显示当天真实的肉
```

## 四、「余额与按营业日推导不一致」黄字告警下线

它拿的是**两个不同时间点**的数：

- 「当前余额」= **此刻**的余额；
- 「按营业日推导的结余」= 被查看的那一天（可能是 3 天前）的**日终**结余。

⇒ 门店翻历史日期时**永远**对不上 ⇒ 每翻一天就多一条黄字
（生产实测 10-29/10-30/10-31/11-01/11-02 每天 2~3 条）。

⇒ 下线（`balance_mismatch` 不再出现在 `alerts` 里）。

**同一天的真实差异仍然看得见**，由这几条覆盖：

| 告警 | 含义 |
|---|---|
| ① 账面短卖（红字） | 账面推演的期末为负 = 卖超了账面库存 |
| ①b 位置表负余额（红字） | 搬台改多了 ⇒ 冷库/柜台走负（**用位置表**：它才是「改过的那个数」落的地方） |
| ①c 分割权重没能重分配（黄字） | 今天的进货权重不是按实际切出来的量 |
| 搭赠/盘亏缺口（搭赠核对卡） | 账面比实盘多出来的量（**这一条才是 owner 报的**） |

## 五、单测与判别力实测

### 新增用例（`internal/fresh-meat/service/counter_derive_test.go`，5 条）

| 用例 | 锁什么 |
|---|---|
| `TestCounter_BackdatedExternalPurchase_NoGhostBalance` | 补录的外采**不变成**柜台上的幽灵货（复刻生产：11-02 收盘 + 11-03 上午补录 11.4kg） |
| `TestCounter_TodayLoadAndSale_NetBalance` | 搬上台 10 − 卖出 6 = 4 |
| `TestCounter_PigProduction_ShowsOnCounter` | 当天切出来的 10kg 猪排**要算在柜台上**（不然柜台恒显示 0） |
| `TestCounter_StocktakeDayEvents_AreAbsorbed` | 盘点日当天的搬台被当晚实盘吸收 ⇒ 不双算 |
| `TestCounter_DeriveDisabled_FallsBackToPositionTable` | 没有盘点单 ⇒ 推不出来 ⇒ 退回位置表且不报错 |

### 判别力实测（**运行期开关**，跑完即恢复）

| 关掉的实现点 | 现象 | 对应用例 |
|---|---|---|
| 柜台推导整体 | 柜台 = **11.4**（幽灵余额回来） | `..._NoGhostBalance` ⇒ 红 |
| 窗口多含锚点当天 | 柜台 = **10**（盘点日当天的搬台被双算） | `..._AreAbsorbed` ⇒ 红 |
| 「分割产出」这一项 | 柜台 = **0** | `..._ShowsOnCounter` ⇒ 红 |

> ⚠️ 开关必须是**运行期变量**（包级 `var`）：写成 `if false` 会被 Go 编译器整个消掉
> ⇒ 那次「去掉实现」的实测是假的。

### 一处既有用例的改动（`TestStock_CounterLoad_MovesFromColdStore`）

该用例的注释本意就是「**次日**搬上台」，但测试的时钟冻结在 D1
⇒ 搬台被记成 D1 ⇒ 与场景本意不符。
柜台改成推导后，**盘点日当天**的搬台已被当晚实盘吸收（柜台那晚被置零）
⇒ 把搬台挪到 D2（`svc.SetClock(fmClock(day2))`）才与生产的真实流程一致。

## 七、遗留 / 未做

- **不推断「外采已售（POS 未登记）」**：系统无法从现有数据区分「外采已售」与「搭赠/盘亏」
  ⇒ 选 owner 的心智模型（当天买当天卖完）作为口径。
  代价 = 当天有外采的部位**当天不再报搭赠**（漏报优于误报 —— 误报会让门店白扣毛利）。
- **不新建交互让门店选「卖掉了」**（同上：无依据可判）。
- **总量短卖口径不动**（`outTotalKg` 不加外采）⇒ 保证该数字与部署前逐位一致。
- 长期毛利页的每日毛利/毛利率是否切当日口径：**仍未拍板**（沿用上一轮）。
- 前端无需改动：App 不展示 `balance_mismatch`，搭赠卡直接读 `/gift-suggestions`
  ⇒ 后端不再返回那条建议 ⇒ 卡片自然消失。
