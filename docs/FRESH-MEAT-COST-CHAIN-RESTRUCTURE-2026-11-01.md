## 2. 链 A：header 毛利（与分割无关）

### 2.1 输入
| 符号 | 来源 | 备注 |
|---|---|---|
| 总采 | `whole_pigs`（当日进店） | 重量、采购金额、猪价 |
| 总售 | cube 零售 + 统收 | 重量、金额 |
| 总剩余 | 盘点单 **猪肉台实盘** | **不含冷库**（owner 拍板） |
| 期初剩余 | **恒为 0** | 夜里柜台清空、货回冷库 ⇒ **冷库才是跨日结转的位置** |

### 2.2 公式（**已落地**）
```
采购均价 = 采购金额 ÷ 采购重量
剩余成本 = 期末台面剩余kg × 采购均价      （粗估；owner：「可以用采购均价计算」）
m = ( 营收 − 采购金额 + 期末剩余成本 ) / 营收
```
- **期初剩余 = 0** ⇒ 公式里**没有跨日项** ⇒ 单日闭环（跨日在冷库，长期毛利页看）
- 剩余成本按**采购均价**估值 ⇒ **不含 m ⇒ 永不成环** ✔（owner：「不会成环」）
- **当剩余趋于 0 时，m = (营收 − 采购)/营收 ⇒ 精确** ✔（owner 自己的判据）
- 全部输入都是量与金额 ⇒ **没有一个来自分割建议** ⇒ 分割再不准，header 毛利不动 ✔
- ⚠️ **没有完整日终盘点 ⇒ m 算不出来** ⇒ 毛利给「—」，**不给 0**
  （0 会被门店误读成「当天一点货都没剩、还亏了本」）
- ⚠️ 代价（owner 知情选定）：单日毛利会偏高（今天卖昨天结转的货，那笔成本昨天已扣）
  ⇒ **跨期才平**；owner：「十分准确的销售成本基本算不出来」

### 2.3 搭赠
搭赠从**猪肉台**出（有成本、无收入）⇒
- 链 A 里：搭赠会让剩余变少 ⇒ 已被"库存变动"项捕捉 ⇒ **不单列**
- 部位层：搭赠成本_c = 成本单价_c × 搭赠kg_c ⇒ 从部位毛利里扣

### 2.5 ⚠️ 一条必须补的口径闸：**当天没有进货 ⇒ 参考毛利算不出来**（2026-11-01 补）

公式 `m = (营收 − 采购 + 期末剩余×采购均价) / 营收` 在**当天没有进货**时：

```
采购 = 0  ⇒ 采购均价 = 0  ⇒ 期末剩余×0 = 0  ⇒  m = (营收 − 0 + 0) / 营收 = 100%
```

⇒ 门店会看到「参考毛利 = 营收、参考毛利率 **100%**」⇒ 以为赚疯了。
而那种日子通常只是**还没录猪**（毛利看板本来就有「今天还没录猪」提示）。

⇒ 处置：`referenceMarginRate` 加判据 `PurchasedKg > 0` ⇒ 算不出来时**返回 nil**，
前端显示「—」（**不是 0、不是 100%**）。
判别力：`cut_margin_dayend_test.go:TestReferenceMarginNeedsPurchase`（去掉判据必红）。
长期毛利页的每日行同理 ⇒ 新增 `has_purchase` 字段（老后端没这个键 ⇒ 前端按「有进货」处理）。

### 2bis.2 口径

```
期间毛利 = 期间营收 − 期间采购 + (期末冷库量 − 期初冷库量) × 期间采购均价
每日毛利 = 营收_d − 采购_d + 期末台面_d × 当日采购均价      （= 每日毛利看板同一个数）
```

- **库存一律按期间采购均价估值**（一个价到底）⇒ 口径统一、可自洽、不成环。
- **全店结余 = 冷库量**（冷库的日终余额**已经含**夜里从柜台搬回去的那部分）
  ⇒ **不能再加一次台面实盘**（否则重复计库存）。这条已单测锁住。
- 每日行与期间值**不相等**（口径差）⇒ 两个数都给 + note 说明 ⇒ 店长能自己核对。

## 3. 链 B：部位成本单价与参考毛利（定价倒推）

```
部位成本单价_c = **建议成本单价**(分割基线的部位单价 × 今天这头猪的进价折算)
参考毛利_c     = 营收_c − 成本单价_c × (销量_c + 搭赠_c + 报损_c)
全店参考毛利   = **Σ 部位参考毛利**（头与部位同源）
```
- **统收不单列**：营收_c 与销量_c 都**含统收** ⇒ 统收成本已被"单价×销量"涵盖
- **兜底价**：某个部位**没有自己的基线价** ⇒ 用**全店采购均价**，来源标记 `purchase_avg`
  （前端要能说清这个价是基线折算的还是兜底的）
- **header = 部位之和**（v3.5 起）⇒ 门店能自己核。
- **不需要跨日**：报表当天的成本单价是单日闭环。
  跨日只在**新猪预估**那条辅助通道：`比值_c = 成本单价_c ÷ 猪价`，用历史比值估另一头猪。
- 「建议毛利 / 建议毛利率」**删除**（m 进去、m′ 出来 ⇒ 数学上永远对不上 header）。

### 3.0 ⚠️ v3.5：参考口径切 **B**（owner 2026-11-01 第三轮拍板）

#### owner 的原话（这次是**他提的算法**，不是我提的）

> 「在录入猪的时候不是应用了 auto 基线计算吗？不是会有 7.3 元/斤猪价的成本单价？
>   然后根据分割基线，销售重量×建议成本单价不就有了销售成本，
>   销售重量×销售单价−销售成本，不就有当前毛利吗？
>   难道你的参考成本单价还是当天算出来的？而不是使用基线里的成本单价？这是缺数值的原因？」

#### 为什么换（旧口径 A 的硬伤）

```
旧口径 A：部位成本单价_c = 零售均价_c ÷ (1 + m)，而 m = (营收 − 采购 + 期末台面剩余×采购均价) ÷ 营收
        ⇒ m 依赖**日终实盘** ⇒ 门店当天没做日终盘点 ⇒
          m / 成本单价 / 参考毛利 / 毛利率 / 售罄率 **连锁算不出来**
          ⇒ 界面一片「—」（生产实测 店 00 2026-11-01：营业额、进货、产出估值都有，
            毛利/毛利率/售罄率/日终剩余/出成率/参考成本单价/部位参考毛利全是「—」）
新口径 B：部位成本单价_c = 建议成本单价（录猪时就算好的）
        ⇒ **不需要日终实盘** ⇒ 没盘点也有数
```

#### 两套口径的交叉对比（**先在有数据的历史日对比，再决定换不换**）

店 00 实测（B = 销量 × 建议成本单价；A = 旧口径）：

| 营业日 | A 旧口径 | B 新口径 | 差 |
|---|---|---|---|
| 10-29 | 949.49 / 26.72% | 952.42 / 26.80% | **+2.93**（几乎一致） |
| 10-30 | 1384.13 / 32.22% | 923.02 / 21.49% | **−461.11** ⚠️ |
| 10-31 | 1166.70 / 27.14% | 1153.82 / 26.84% | **−12.88**（几乎一致） |
| 11-01 | **null（算不出来）** | **1135.75 / 26.29%** | ← 没盘点也有数了 |

⇒ **分歧集中在 10-30 一天** ⇒ 回头查那天的输入 ⇒ 台面期初 0 + 产出 − 销售 = 期末台面
⇒ 解出**产出 238.73kg > 当天进货 227.1kg** ⇒ 物理上不可能 ⇒ 出成率 106.45%
⇒ **那天的期末实盘本身不可信**（搬台没登记 / 盘点漏了部位）⇒ A 的 32.22% 很可能被它抬高。
⇒ 两套口径各赌一样（A 赌期末实盘、B 赌基线单价），**不能证明 B 更对，只能说 10-30 的 A 不可信**。

#### ⚠️ 三条取舍（owner 知情选定）

1. **依赖统计基线**：建议成本单价是"分割基线 × 今天进价"折算出来的统计量，
   不是这批货的实际成本（今天卖掉的货可能还是前几天进的猪）。
2. **偏差方向与旧口径相反**：旧口径把"今天进货但没卖掉"算进今天（单日毛利偏高）；
   新口径只给"今天卖掉的货"计成本（猪价涨了当天毛利偏低）⇒ **两者只能选一个**。
3. **当天没进货 ⇒ 算不出来**：建议成本单价要靠当天的猪做进价缩放 ⇒ 「—」（不回落成 0）。

### 3.2 「哪个部位更赚钱」到底能算什么（owner 2026-11-01 提问后的正式答复）

owner 提问：**取消摊销之后，还能算「哪个部位更赚钱」对吧？**

#### ✅ 能算的（数据已经在接口里，门店手机上就能看）

**① 毛利额（¥）** —— 字段 **`reference_gross_margin_yuan`**（毛利看板的部位表已经有这一列）。


⇒ 所有部位**共用同一个率** `m/(1+m)` ⇒ **按毛利额排序 ≈ 按营收贡献排序**（再扣掉搭赠/报损）。

⇒ 部位合计 1002.61 vs header 1384.13，这个差是**口径差，不是算错**。

**② 定价空间（加价空间）** —— `actual_avg_unit_price_yuan` − 当天全店采购均价（`purchase_avg`）。

店 00 2026-10-30 实测：猪肚 +45.20 / 肋排 +31.14 / 尾·心·舌 +23.00 / 肩胛·肋骨 +13.00 …
反过来，**零售均价低于全店采购均价**的部位：后腿 −0.64 / 小肠 −2.64 / 里脊 −4.64 / 筒骨 −4.70 /
猪油 −8.60 / 肺 −8.60 / 脾 −13.60。
⇒ 这是**定价信号**（哪些部位贴着进货价卖、哪些在贴钱走量），**不是**利润率。

#### ❌ 算不出的：部位的「真实利润率」

数据里**不存在部位级的真实成本**：

- 取消摊销后，整猪是**按重量买**的，不是按部位买 ⇒ 没有部位真实成本；
- 账面链那套部位成本单价（`moving_avg_unit_cost` / `sales_cost_yuan`）**本身就是摊销的产物**（一个分摊结果），
  拿它回答"哪个部位利润率最高"= 用**我们怎么分摊**去回答**哪个部位更值钱** ⇒ 结论会跟着分摊规则漂；
- 连带算不出：**部位占用的资金、周转天数**（分母要部位库存金额，同样依赖摊销）。

⇒ 要部位真实成本只有两条路：
1. 供应链给**分部位收购价**（猪场/批发商其实常有"前腿/后腿/五花"的收购价，只是目前按头卖）；
2. 恢复摊销（owner D6 已否）。

⇒ **结论**：owner 问的「哪个部位更赚钱」——
- 若指**赚多少钱（总额）** ⇒ 用**毛利额排行**（字段已有，只需排序）；
- 若指**赚多少%（利润率）** ⇒ 在拿到分部位采购价之前，任何答案都是编的。

### 3.3 价值系数与产出估值（2026-11-01 owner 第二轮拍板，已落地）

owner 看完毛利看板后提了两条（原话见下）：
> 「header处毛利的两个值是不是销售总价-购猪成本算出（假设0库存）？如果是那么他的真实性比较大，
> 所以可以去掉"参考"两字。增加加权价值产出 = Σ（某部位实际产出重量 × 该部位价值系数）」
> 「部位明细处，参考毛利率已经一致，无显示必要，可以去掉该列，改为价值系数。
> 价值系数 = 该部位的单位重量市场价值 ÷ 整扇猪分割后所有可售部位的平均单位重量价值。」

#### ① 前提纠正：参考毛利 **≠**「销售总价 − 购猪成本」

```
参考毛利 = 营收 − 采购金额 + 期末猪肉台剩余 × 采购均价
```

**只有当天卖光（期末剩余 = 0）时**才等于「营收 − 采购」。
店 00 2026-10-30：参考毛利 **1384.13**；按 owner 的假设算 = 4296.10 − 3315.66 = **980.44**，
差 **403.69** = 27.65kg 台面剩余 × 14.6。

⚠️ 差的这 403.69 **是对的** —— 没卖掉的货不该算今天的成本
⇒ 「假设 0 库存」那个数反而**更不准**（它把冷库 57.4kg 压货 + 损耗 + 搭赠 + 10-30 超产 11.6kg
的成本全部算成了今天的消耗）⇒ **公式不动**。

⇒ 但「参考」二字**去掉**（owner 2026-11-01 拍板）：界面「参考毛利 / 参考毛利率」
⇒ 「**毛利 / 毛利率**」，**口径与 API 字段名不变**（仍是 `reference_gross_margin_*` ⇒ 留档这个映射）。
⚠️ **部位的「参考毛利」列保留原名** —— 部位那个数是**分摊出来的**（所有部位共用一个率），
不是真的部位毛利；header 那个才是「今天卖掉的货的毛利」
⇒ 页面口径说明写明「header 的『毛利』与部位的『参考毛利』口径不同，**不能相加或互相对账**」。

#### ② ⚠️ 「加权价值产出」按字面算是**恒等式** ⇒ 已改成「产出估值」

因为「平均单位重量价值」本身就是**产出加权**的平均：

```
平均单位价值 = Σ(kg_c × price_c) ÷ Σ(kg_c)
⇒ Σ(kg_c × 系数_c) = Σ(kg_c × price_c) ÷ 平均单位价值 = **Σ(kg_c)**（= 产出总重）
```

生产实测 店 00：10-29 = 197.899 / 10-30 = 238.726 / 10-31 = 215.596 kg
—— 与同三天**产出总重**三个数**逐一相同** ⇒ 不含任何新信息。

⇒ owner 2026-11-01 拍板：这一项改成 **产出估值（¥）**：

```
产出估值 = Σ(实际产出kg_c × 该部位零售均价_c)
```

含义：**今天切出来的货，按零售价算值多少钱**（含还没卖掉的、损耗的、搭赠的）
⇒ 与当日营收对照，差值就是「切出来但还没变成现金」的那部分价值。

#### ③ 价值系数的口径

```
价值系数_c = 该部位的单位重量市场价值_c ÷ 全店平均单位重量价值

  该部位的单位重量市场价值 = 该部位当天实际卖出均价（零售均价，含统收）
  全店平均单位重量价值   = Σ(kg_c × price_c) ÷ Σ(kg_c)
                            （只在「有实际产出重量 且 当天卖过」的部位上计算）
```

owner 拍板：**当天没卖过、取不到零售价的部位 ⇒ 不计入、不提示**
（既不进分母、也不产出系数；页面上该格显示「—」）。

生产实测（店 00）：
| | 10-29 | 10-30 | 10-31 |
|---|---|---|---|
| 产出估值 | 3892.61 ¥ | 4761.13 ¥ | 4341.13 ¥ |
| 平均单位价值 | 19.6697 元/kg | 19.9984 | 20.1355 |
| 猪肚系数 | 3.04 | 2.99 | 2.97 |
| 肋排系数 | 2.66 | 2.29 | 2.12 |

#### ④ 两个必须写明的前提

- **产出重量是推导值**：`actual_split_kg` 在多数日子是**倒推值**（derived）
  ⇒ 价值系数与产出估值都带着分割估算的误差（真实切分产出目前只有**全店合计**、没有部位级）。
- **部位「参考毛利率」那列为什么能删**：它恒等于 `m/(1+m)`（一列常数），
  部位层真正有信息量的是**参考成本单价**与**价值系数**。

⇒ **现状：改那天的搬台或猪重 → 重算基线 → 样本会变** ⇒ 与 owner 期望相反。

⇒ **P3 必须改成**：分割基线样本 = **cube 逐部位销售重量**采集，归一后**直接存产出率**
（`日产出率_c = 当日销量_c ÷ 当日总猪重`），一行存比率而不是绝对 kg
⇒ 这样**连"猪重事后被改"都不会影响已采集的样本**（比率在采集时已固化）⇒ 性质彻底成立。
